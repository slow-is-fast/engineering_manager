## 2. 与 audit.py 的边界

`audit.py`（EVD-01/EVD-02）回答**"这条链有没有被动过"**——哈希链 + 不可用即
失败关闭。本模块管**写完之后**：该留多久、谁写的、坏了之后怎么接着用。

三件事共有的原则是**不得静默**：
- 超期没删要说
- 来源可疑要说
- 恢复丢掉的段落要**原样交出来**——静默丢弃被篡改的段落，等于替篡改者擦掉痕迹

## 3. 保留策略

| 情形 | 判定 |
|---|---|
| 在保留期内 | 通过 |
| 超过登记上限 | `EXPIRED` |
| **类别从未登记保留期** | `UNDECLARED`——不得无限期保留 |
| 时间戳缺失/不可解析 | `UNKNOWN_AGE`——**不是**"没超期" |
| 要删除 | 必须有 `approver`，不得自批 |

"没人说过要留"不等于"可以一直留"。保留是授权，不是默认权利。

## 4. 伪造来源识别

四类可疑：`missing_source` / `undeclared_source` / `event_type_out_of_scope` /
`source_seq_replay`。未登记来源按可疑处理（没登记过 ≠ 允许）。

`audit.py` 新增 `append_from(source, event_type, **fields)` 写入来源字段。
**单独开方法而不是给 `append` 加关键字**：`append(event_type, **fields)` 的
fields 是开放的，加 `source` 参数会和同名业务字段撞车。

## 5. 恢复

截断或篡改后取回最后可信前缀，返回 `recovered` / `dropped` /
`last_trusted_seq` / `reason` / `complete`。`dropped` 原样返回而非丢弃。

## 6. 诚实边界（写进模块文档，并固化成用例 T-ALC-17）

**单个审计文件证明不了写入者是谁。** 持有写权限的人可以自己写上任意来源
字段。本模块能做的是**内部一致性检查**，不是身份证明。把一致性检查说成身份
证明，正是本规范一直在防的那种夸大。真正"来源独立可证"依赖审计后端的权限
分离与独立存储——那是 `AUD-014-04`（manual）。

## 7. 变异检验：16 个，全部捕获、0 逃逸

**其中一轮抓到一处逃逸并修掉**：把 `seq` 校验改成恒假，没有任何用例会发现。
原因是我此前三条恢复用例（T-ALC-15/16/18）实际都只被 hash 校验兜住——
seq 分支从未被单独验证过。

它防的是一个真实场景：**删掉一条事件后把后面的链重新算一遍**。此时
`prev_hash` 与 `hash` 全都自洽，唯一露馅的是编号跳号。补 `T-ALC-18`
（构造一个哈希自洽但 seq 跳号的流）后才归零。

顺带修正自己写变异脚本的一个错误：第一版把 `if prev_hash...` 整块删掉，
导致后面的 `elif` 悬空 → 语法错误 → 那是**收集失败**而不是真变异。
改成只把条件换成 `if False:`、保留 if/elif 结构。

## 8. ref 覆盖问题（第二次遇到）

`AUD-014-03` 覆盖保留策略 + 来源识别 + 恢复**三件事**，而验收矩阵每条断言的
`ref` 只能指一条用例。T-ALC-02..18 各自只测一件，指过去会丢掉另外两件。
补 `T-ALC-19`（在同一条审计流上走完三者）并定向验证：保留判定放宽、
来源标记被换掉这两个变异，T-ALC-19 都会失败。

这与上一轮 AUD-009-03 / AUD-010-03 遇到的情形相同——**一条断言覆盖多个语义
时，单点用例会让记账失真**。
