## 组件与覆盖的控制

| 组件 | 规范依据 | 实现要点 |
|---|---|---|
| `executor/lock.py` | WF-02 / CNC-01（v1.1.1 §5） | fencing token 单调递增；过期需重取；validate_write 拒绝旧 fence；存储损坏时失败关闭 |
| `executor/ledger.py` | EFF-01 / WF-03（§6） | 幂等键台账先于副作用；CONFIRMED 后重投拒绝；并发重复返回既有；UNKNOWN 只能经 reconcile 退出 |
| `executor/memory.py` | CTX-02 / CTX-03 / MEM-01（§4） | DRAFT→PENDING_REVIEW→APPROVED→REVOKED；作者不能自批；CAS 版本控制；撤销与检索过滤同事务 |
| `executor/checkpoint.py` | REC-01 / CKP-01（§7） | (baseline,payload) 绑定摘要；摘要不符=损坏；基线变化/授权失效 → 暂停 |
| `executor/breaker.py` | REC-03 / BRK-01（§7） | 按原因码阈值累计（5 分钟窗口）；severe 立即熔断；open 时拒绝一切新副作用 |
| `executor/handoff.py` | WF-01 / SMT-01（§5） | 七要素契约校验；policy_hash 必须与本地一致；终态任务拒绝交接 |

每个组件的状态变更都写入 append-only 审计流（`executor/audit.py`，EVD-01 简化实现）。

## 负向用例结果（10/10 通过）

| 用例 | 注入 | 断言的拒绝行为 |
|---|---|---|
| T-WF-01 | 缺 policy_hash / policy 不符 / 终态任务交接 | 全部 REJECTED；合法契约 ACCEPT（对照） |
| T-WF-02 | 未过期时第二持有者抢锁 | LockDenied |
| T-CNC-01 | 锁过期后旧持有者写 / 锁存储损坏 | StaleFence；损坏时报错而非放行（失败关闭） |
| T-WF-03 | CONFIRMED 后重投 / 并发重复 | DuplicateRejected；返回既有记录不重放 |
| T-EFF-01 | UNKNOWN 状态下重放 | UnknownResult，必须先 reconcile |
| T-CTX-02 | 撤销后的记忆进入规范性检索 | 不可见（撤销与过滤同事务） |
| T-CTX-03 | DRAFT 直接晋升 / 作者自批 / 过期版本 CAS | 全部 InvalidTransition |
| T-REC-01 | 快照不存在 / 基线变化 / 授权失效 | Corrupted / BaselineChanged（暂停） |
| T-REC-03 | 连续 3 次网络错误 | 第 3 次熔断，新副作用 BreakerOpen |
| T-BRK-01 | 单次严重越权 | 立即熔断，不等阈值 |

**过程发现并修复的真 bug**：handoff 校验器最初把空列表 `artifact_manifest: []` 误判为字段缺失（`not value` vs `value is None`）——正向对照用例抓住的。空 manifest 合法，"有值"与"非 falsy"是两回事。
