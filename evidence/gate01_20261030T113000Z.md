## 判定器语义（全部失败关闭）

1. **输入缺失**（等级矩阵 / 控制目录 / 规则注册表 / 审计清单）→ `GateInputError`，不给结论；
2. **事实源冲突**：同一审计问题在 §四（权威）、§二·A、§12.1 三处严重程度不一致 → `GateInputError`——不任选其一；
3. 控制未 tested / 未 verified / 缺 `evidence_at` / 证据超 TTL → 计入 blockers；
4. **例外采信条件**（全部满足才豁免）：ACTIVE + 人类批准人 + 未到期 + 有补偿控制 + 有撤销条件 + `waives` 覆盖目标 + `waives_requirement` 类别匹配；
5. **GATE-01 自身不可被豁免**（判定器不得被自己的豁免关掉）；
6. 豁免只豁免其声明的那一项；控制只要自称 tested，证据新鲜度不受豁免（RVF-01 独立约束）；
7. R2/R3 需**人类主体**逐案评审（`approval_ref` + `principal_type=human`），且逐案评审不降低等级门槛；
8. 达到 G3 时 G4 的未完成项**不**阻断只要求 G2 的 R0 申请（门槛不是永远拒绝）。

## 诚实边界

- 判定的是**治理账本自身的完整性与新鲜度**；条件取值来自仓库自报的状态字段。控制面与数据面同属一个 GitHub 账号（EXC-02），判定结果无独立第三方背书。
- tested ≠ verified：只有 G4 要求 verified；当前 verified=0，R3 在 EXC-02 撤销前不可达——这是事实，不是缺陷。
- GATE-01 置 tested 指判定器**本身的逻辑经 31 条用例验证并失败关闭**；它判定出的"当前 G1"这一结论与其自身的 tested 状态不矛盾（判定器可用 ≠ 账本达标）。
