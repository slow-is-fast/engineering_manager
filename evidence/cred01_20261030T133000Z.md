## 守卫语义（全部失败关闭）

| 环节 | 强制条件 |
|---|---|
| 访问控制（SEC-006） | Agent 主体对受保护目标（production_credential / ssh_private / cloud_admin_token）一律拒绝 + `credential.access_denied` 落审计；**未分类目标默认按受保护处理**（不因"没标"而放宽）；白名单人类放行；自称 human 但不在白名单 → 拒绝（主体声明不构成授权） |
| 形态扫描（SEC-007） | 提示文本/日志提交前扫六类已知凭证形态（github_pat_ / ghp_ 系 / PEM 私钥块 / AKIA / xox- / sk- 前缀）；命中记 `credential.exposure_detected`；**补救必须闭环**：轮换确认 + 事件登记两项齐备，缺一即 `remediation_rejected` 失败关闭 |
| 停用请求（SEC-008） | `disable_audit` / `skip_quality_checks` / `suppress_alerts` 一律拒绝——Agent 无此权限；人类经由本守卫请求同样拒绝（**正确通道是变更管理 CHG-01**，不得走捷径） |

## 诚实边界

- **形态扫描是启发式检测而非穷尽保证**：未知格式、编码/分段变体不保证被识别；真正的强制层是 OS 与秘密管理层权限（检测层 ≠ 强制层），不得据本模块宣称"凭证不可能泄露"；
- 主体白名单是进程内判定，不代替身份服务（AUTH-01/02 未落地，见 G2 阻断项）；
- 与 INC-01 的衔接是**约定级**（`incident_declared` 布尔确认），未自动实例化 IncidentWorkflow——自动化衔接属后续工作。
