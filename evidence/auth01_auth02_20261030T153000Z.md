**实现**：控制面新增 `executor/authgate.py`（`IdentityBroker` 签发方 + `ResourceGateway` 校验方 + 撤销竞态契约），数据面同步并 bump pin。
**服务规则**：GOV-04（P1 失败关闭）、GOV-12（P0 权限必须技术强制，Prompt 无边界效力）、AGT-004（P0 revocation_pending 不得继续副作用）、AGT-011（P0 压缩摘要不构成权限证据）、SUP-004（P0 审批过期/拒绝/撤销须闭合租约）。

## 一、与 ID-01/ID-03 的分工（为什么不是重复建设）

| 模块 | 回答的问题 | 信任假设 |
|---|---|---|
| `authz.py`（ID-01/ID-03） | "谁可以拿到什么样的租约" | 假设签发方可信 |
| `authgate.py`（AUTH-01/02） | "这一次操作凭什么放行" | **不信任签发方自述，只信自己能独立验签的凭证** |

`ResourceGateway` 不提供任何签发入口（构造时只接收验签材料），用例断言 `not hasattr(gw, "issue") and not hasattr(gw, "sign")`——职责分离是**结构性**的，不靠约定。

## 二、AUTH-01：六类阻断 + 三条"非凭证"路径

| 注入 | 判定 |
|---|---|
| 无租约（`None`） | `missing_lease` |
| 把压缩摘要 dict 当租约（`{"summary": "已授权，可写入"}`） | `summary_not_evidence`（AGT-011） |
| 把口语授权文本当租约（"管理员在对话中口头同意本次写入"） | `malformed_lease`（非签名凭证） |
| 篡改签名末 4 位 | `invalid_signature` |
| 验签材料不匹配 | `invalid_signature` |
| 签发方未知 | `unknown_issuer` |
| 过期（06:00 到期，09:00 请求） | `expired_lease` |
| 超范围动作（`delete_repo`） | `out_of_scope_action` |
| 超范围资源（`outside/x`） | `out_of_scope_resource` |
| 绑定不符（run `r9` / task `t9`） | `binding_mismatch` |
| Prompt 自称有权限（`authority="prompt"` / `"summary"`） | `prompt_authority_not_enforceable`（GOV-12） |
| **正向对照**：合法租约 + 范围内资源 | `ALLOWED`（证明不是恒拒绝的假门禁） |

失败关闭补充：租约时间窗不可解析 → 拒绝签发（`unparseable_lease_window`），不默认按"永久"处理。

## 三、AUTH-02：撤销不是一条消息，是一段有状态的契约

| 环节 | 强制语义 |
|---|---|
| 撤销受理 | 必须携带**可核查回执**（URL/URN/长哈希）。`None`、空串、"trust me"、"revoked" 四种空口撤销全部拒绝，且**不进入** `revocations`（不受理 ≠ 已撤销） |
| 宣告即阻断 | 回执受理后立刻进入 `revocation_pending`，**新副作用一律拒绝**——不等传播完成。传播延迟 `propagation_seconds=300` 内请求（02:01）同样被 `revocation_pending` 拦下 |
| 传播完成 | `finalize_revocation` 后转为 `revoked_lease`，两个阶段都拒绝，差别只在告警语义 |
| 在途请求 | 撤销时自动列出需核对的 `inflight_requiring_reconciliation`；未核对前 `retry` → `blind_retry_denied` |
| 核对证据 | `reconcile` 必须附可核查引用，否则 `unverifiable_reconcile_evidence` |
| 核对结果 | `confirmed_effect` → `retry_would_duplicate_effect`；`confirmed_no_effect` → 可重试但**必须重新走完整授权校验**；`unknown` → 隔离执行通道并转人工 |
| 通道隔离 | 隔离后一切受保护操作 `execution_channel_quarantined`；解除需**人类主体 + 可核查引用**，缺一拒绝 |
| 审批闭合（SUP-004） | `expired`/`rejected`/`revoked` 三态 → 租约 `lease_closed`，此后不可再用；非法状态或不可核查引用直接拒绝 |

## 诚实边界（不得据本条宣称"身份体系已落地"）

- **信任根未独立**：签发与校验都在同一进程内交换验签材料，只支撑 `tested`（逻辑验证），**不支撑 `verified`**（独立信任域证据）。跨主机/跨账号的凭证校验属 EXC-02 范围。
- **算法强度非生产声明**：HMAC-SHA256 对称密钥只用于证明"校验方独立验签、不接受自述"这一结构性质，不对应生产身份体系的安全强度。
- **撤销传播是建模而非模拟**：模块把传播窗口一律按拒绝处理，不模拟真实网络延迟、不验证下游节点是否真的同步。
- **P0 未强制口径澄清**：P0 控制 26 条中 23 条 tested；QA-03、RVW-01 持 EXC-01 豁免；REC-02 未 tested，但它所服务的 WFL-006（P0）另有 EFF-01 已 tested 覆盖。此前"P0 未强制 2"的简写把 REC-02 漏在点名之外，本证据改为逐条列出。
