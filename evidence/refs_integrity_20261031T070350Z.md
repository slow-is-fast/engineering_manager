## §10.27.1 起因：四个查不到的编号

同一天早些时候发现，`ALC-01` / `DG-01` / `REM-01` / `REM-02` 被写进了四类地方：

| 出现在哪里 | 实际是什么 |
|---|---|
| commit message | 自称受控制管着 |
| `governance/audit_policy.json` 的 `control` 字段 | 机器读的"归属控制" |
| `governance/evidence_ledger.json` 的 `control` 字段 | 同上 |
| CI 步骤名 `T-ALC-01` | 看起来像验收用例 |

而它们在 `rule-registry.json`（53 条）与 `control-catalog.yaml`（49 条）里
**都不存在**。

一个查不到、但看起来像控制的编号，比没有编号更糟：没有编号的人知道自己没
编号，编一个出来的人会以为"这条已经被某条控制管住了"。而当时没有任何机器
判定能发现它——`validate_controls.py` 校验的是注册表与控制目录之间的**双向
一致性**，它不扫引用方。这条检查补的正是引用方那一半。

## §10.27.2 为什么只查字段、不扫全文

用正则扫全文会误报：`PR-01`、`SHA-256`、`2027-01-31` 的片段都能命中 ID 形状。
误报的下场通常不是被人修正，而是被人把检查关掉——一个被关掉的检查等于没有
检查，而且比没有更糟，因为矩阵上还挂着"已配置"。

所以这里只校验**结构化字段**：字段名在 `REF_FIELDS` 里、且字段值长得像编号时，
才要求它解析得到真实对象。可解析的命名空间：规则 / 控制 / 例外 / 审计问题
（含 `AASEGS-` 前缀形式）/ §四 断言。

**代价要写清楚**：commit message、CI 步骤名、Markdown 正文里的编号，这条检查
管不到。它们是散文，不是字段。当年那四个编号正是从散文里开始的。

## §10.27.3 变异检验逼出来的一处收紧：豁免清单

第一轮变异设计到"往豁免清单里加一项前缀"时，发现这道闸门当时守不住：

- `PREFIX_FREE` 里躺着 `"G"` 和 `"R"` 两个**单字母**条目，它们和第二重判断
  合取后永远为假——死配置。死配置不是中性配置，它是个等着被踩的陷阱：哪天
  有人把判断简化成"只看前缀"，`REM-01` 这类编造编号就整体豁免了。
- 实测把豁免清单**整个拿掉**，本仓库依然是 0 处 finding。也就是说 `AUD-` /
  `AASEGS-` / `EXC-` 本来就能解析，它们的豁免是多余的。

于是收窄到只剩 `T-`（用例名确实不在这条脚本能枚举的命名空间里，是否存在由
审计闭环判），并把清单内容用 `test_T_REF_10_exemption_list_is_pinned` 钉死：
改清单必须同时改那条用例，逼着改动者把理由写下来，而不是顺手加个前缀让 CI
变绿。放行是这条检查唯一会被打败的方式，所以它必须是全脚本最难改的一行。

顺带修掉一处噪音：悬空的 `exception_ref` 原先会被通用解析和专门检查各报一次。
同一件事报两遍不是更严格，是噪音——噪音的下场和误报一样。现在专门检查独占
这个字段。

## §10.27.5 顺带修掉的另一处记账缺陷

首次运行即报出：

```
[exception_expiry_mismatch] quality_baseline.json EXC-01 ::
  到期日不一致：例外登记 2027-01-31 / 基线 2027-04-30（以例外登记为准）
```

两处都声称"EXC-01 什么时候到期"，差三个月，而 `exception_valid` 的未过期判定
依赖它——这直接决定"哪一天突然变红"。已按例外登记（登记文件自述"以本文件为
准"）修正基线为 2027-01-31，方向是收紧。

## §10.27.6 诚实边界

1. **不扫散文**：commit message、CI 步骤名、Markdown 正文里的编号不在覆盖内。
2. **只扫 `governance/*.json`**：`rule-registry.json` 与 `control-catalog.yaml`
   是编号的定义方，不是引用方，不参与扫描。
3. **解析得到 ≠ 引用正确**：一个编号能解析，只说明它存在；它是不是这条控制
   真正该引用的那条，机器判不了。
4. **不闭合任何 §四 断言**：它是新增的治理卫生守卫，不是 AUD-001..022 里任何
   一条的验收证据。它和 AUD-001 的"追踪覆盖率 100%"有关（补的是引用方那一
   半），但不声称闭合它。

## §10.27.7 仍未闭合的缺口（需 Owner 决策）
