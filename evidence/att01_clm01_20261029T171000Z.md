## 2 · CLM-01（数据面 `scripts/check_claims.py`）

扫描 17 份规范/证据文档，检出"无证据支撑的绝对化能力声明"（即时撤销、立即失效、完美撤销、零延迟、永不失效、绝对可靠、万无一失，以及撤销语境下的 `100%`）。

| 用例 | 注入 | 结果 |
|---|---|---|
| 负向 | "本系统支持即时撤销，权限立即失效，100% 生效" | ✅ 非零退出 |
| 正向 A | "撤销传播实测 P95=820ms，evidence: run 40844814576" | ✅ 放行（有实测与证据） |
| 正向 B | "覆盖率达到 100% 不代表控制有效率为 100%" | ✅ 放行（免责声明） |
| 回归 | 仓库自身 17 份文档 | ✅ PASS |

**lint 调参过程记录（三次误报修正）**：
1. 初版把任意 `100%` 当违规 → 误报覆盖率目标与会话存档里的 `height="100%"` HTML → 改为"仅撤销语境 + 跳过存档文件 + 跳过代码行"。
2. 仍误报"这不代表控制有效率为 100%"（句中含"失效"）→ 增加**否定/免责豁免**（不代表/不等于/并非/不能证明/不构成/不宣称）。
3. 教训：声明类 lint 的难点在**语义**而非正则；误杀免责声明会惩罚诚实文档，属于反效果。
