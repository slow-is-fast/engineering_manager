# RVF-01 演练证据：证据新鲜度与持续复验（2026-10-29T18:15+08:00）

**控制**：RVF-01（P1）· **用例**：T-RVF-01 · **规则**：AUD-022「证据过期和控制退化缺少持续复验规则」

## 1 · 为什么必须做

治理证据会过期：分支保护可能被回退、CI 可能被改、pin 可能被换、控制可能悄悄退化。
没有复验机制时，"tested" 会随时间变成假话。本次把"证据新鲜度"变成**机器判定**。

## 2 · 机制

- 每条 `tested`/`enforced` 控制必须带 `evidence_at`（验证发生日）；
  `scripts/validate_controls.py` 新增断言：缺时间戳即 lint 失败（无时间戳 = 无法复验）。
- TTL 按风险等级：**P0 = 30 天 / P1 = 90 天 / P2 = 180 天**（未标风险默认 90）。
- `scripts/verify_evidence_freshness.py`：
  - 默认：报告（fresh / due / stale / unknown 四类）；
  - `--enforce`：**过期或缺失时间戳即非零退出**（失败关闭），已接入数据面 CI；
  - `--degrade`：把过期控制写回目录 `state.degraded=true, tested=false`（AUD-022 要求的"证据过期会降级"）。
- 复绿方式：重新验证后更新该控制的 `evidence_at` 即可。

## 3 · 测试结果（5/5）

| 用例 | 注入 | 结果 |
|---|---|---|
| 过期证据 | P0 控制 `evidence_at` = 60 天前（TTL 30） | ✅ `--enforce` 非零退出，报 STALE |
| 无时间戳 | P1 控制缺 `evidence_at` | ✅ 非零退出，报 UNKNOWN |
| 新鲜证据 | P0 1 天前 + P2 100 天前 | ✅ 通过（不误杀） |

| 仓库回归 | 本仓库 22 条 tested 控制 | ✅ fresh 22 / stale 0 |

**当前快照（2026-10-29）**：fresh 22 / due 0 / stale 0 / unknown 0。
**自动失效时间表**：P0 证据于 **2026-11-28** 起 CI 转红，届时须复验并更新 `evidence_at`。

## 4 · 诚实边界

- 该机制只能判定"**证据是否过期**"，不能判定"证据所指的控制是否仍然有效"——后者才是复验的实质内容，需要人工/演练重新执行。
- 因此它是**提醒与门闩**（强制复验发生），不是复验本身；不得把"CI 绿"误读为"控制仍然有效"。
