# Software engineering fundamentals — working notes
Status: candidate, not project-specific policy.

- Requirements: define observable outcomes, non-goals and constraints before work.
- Modularity: minimize coupling and document interface contracts.
- Testing: verify behavior and edge cases with executable checks; log what ran.
- Review: independent reviewer examines design, correctness, complexity, security and maintenance.
- Delivery: reproducible build/test, protected merges, rollback and auditable evidence.

Applicability: general practices, adapt to project risk, language, lifecycle and resources.
Limits: guidance does not guarantee correctness; automated test suites may miss failure modes.
