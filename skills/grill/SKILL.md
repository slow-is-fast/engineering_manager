# /grill —— 开工前拷问

## 何时用
- 需求含糊、存在多种合理解读、或会触碰治理文件 / 门禁 / 断言状态时；
- 任何非平凡任务动手之前（改代码不算琐碎即适用）。

## 步骤
1. **先读后问**：读 `AGENTS.md`、`GLOSSARY.md`、`.workbuddy/memory/` 最新日志——能自己找到答案的不要问用户。
2. **一次一组、最多两轮**，每组 3–5 个问题，覆盖：
   - **目标**：成功长什么样？验收判据是什么（用 GLOSSARY 术语表述）？
   - **边界**：明确不做什么？
   - **约束**：必须触碰哪些文件/门禁？有没有不可破坏的现状？
   - **歧义**：列出你发现的 2–3 种解读，让用户选，不要替用户选。
3. **复述确认**：把理解压缩成 ≤5 行的"将要做什么 / 不做什么 / 如何验证"，请用户确认。
4. **落痕**：确认后结论写进当日工作日志；若涉及 Owner 决策点（AGENTS.md §6），必须落到对应治理文档（如 `owner_designations.md`），不得只留在对话里。

## 宪法约束（不得违反）
- 拷问**不替代** Owner 门控（§6）：该停机问的仍然停机问；
- 铁律⑥：对齐结束后、动手改代码前，仍须基线绿确认（`gov_run --all`）；
- 问题里禁止诱导用户同意"放宽门禁 / 跳过验证 / 弱化断言"。
