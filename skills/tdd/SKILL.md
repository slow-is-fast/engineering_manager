# /tdd —— 红绿重构（治理版）

## 步骤
1. **基线绿**：`gov_run --all` 全绿才开始。红了 → 停下报告根因；除"顺手修复使基线变绿"外，禁止任何弱化动作（铁律⑥②）。
2. **红**：先写一个会失败的测试，断言**用户要的行为**（测行为不测实现细节）。运行确认它红，且红的原因是"功能缺失"而非"测试写错"。
3. **绿**：最小实现让测试变绿。不顺手重构、不提前抽象。
4. **证明确实有效**（prove-it-works）：对原始问题场景复现一次修复效果——测试绿 ≠ 问题真的解决了（铁律①的微缩版：case-passed ≠ problem-solved）。
5. **重构**：绿灯保护下清理，每改一步跑相关测试。
6. **收尾验证**（同一把尺子，铁律⑦）：全套件 + 本次触达的 required_checks；verification = `gov_run` 口径，不是临时脚本。
7. **留痕**：当日日志追加（做了什么 / 证据 / 残留）。

## 宪法约束
- 任何一步红了：停下报告，不得弱化测试 / 门禁 / 断言让流程继续（铁律②）；
- 不得为让新测试通过而修改既有断言语义（`acceptance_matrix` 的断言不是随便动的）；
- 测试是治理资产：删测试会使 T-QA-02 计数下降——"删测试让红变绿"是红线。
